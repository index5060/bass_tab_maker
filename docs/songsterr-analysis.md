# Songsterr 기술 분석 — 우리 앱에 참고할 것

조사일: 2026-11-09. 대상: <https://www.songsterr.com>

이 문서의 목적은 bass_tab_maker 설계에 참고하는 것입니다. Songsterr의 콘텐츠를 가져다 쓰지 않습니다. 표의 근거 칸에 확인 수준을 적었습니다.

- **확인:** 페이지, 공개 스크립트, 도움말에서 직접 확인한 것
- **확인(문구):** 앱이 사용자에게 보여 주는 안내 문구로 확인한 것
- **추정:** API 이름 등에서 미루어 본 것

---

## 0. 조사 방법과 지킨 규칙

**본 것**
- `robots.txt`, `ai.txt`
- 공개 안내 페이지: 도움말(`/help`), AI 채보(`/new`), Plus 소개
- 홈페이지 1개, 탭 페이지 1개 (Nirvana – Come As You Are), 헤드리스 Chromium의 기본 user agent로 열기
- 페이지에 들어 있는 서버 렌더 상태(JSON)의 구조 — 키 이름과 메타 정보만
- 페이지를 열었을 때 나간 요청의 종류와 주소 형태 (응답 내용은 저장하지 않음)
- 공개 스크립트에서 쓰는 라이브러리 이름과, 사용자에게 보여 주는 안내 문구 (확인 후 파일 삭제)
- 탭이 화면에 무엇으로 그려지는지 (요소 종류만, 탭 내용은 저장하지 않음)

**보지 않은 것**
- `/api/` 직접 호출, 오디오 파일
- 로그인, Plus 기능

**접근 방식**
- curl로는 탭 페이지가 403으로 막혔습니다. 브라우저인 척 위장하지 않았습니다.

### Songsterr의 정책 (robots.txt, ai.txt 요약)

| 구분 | 내용 |
|---|---|
| 허용 | 사용자 대신 탭 열기·보기, 재생·정지·위치 이동, 연주법 설명, **사이트를 건드리지 않는 독립적인 도구 만들기** |
| 금지 | Songsterr 콘텐츠(탭, 메타데이터, 오디오, API 응답)로 AI 모델을 **학습·미세조정·평가**하는 것, 그런 데이터셋을 만드는 것 (서면 허가 없이) |
| 금지 | Plus 기능을 스크립트, 플레이어 조작, 응답 변조 등으로 우회하는 것 |
| 크롤러 | `/api/`, 오디오 CDN 경로 등은 크롤링 금지. AI 학습용 크롤러(GPTBot, ClaudeBot 등)는 전체 금지 |
| Plus 기능 | 원곡 오디오와 끊김 없는 싱크, 감속, 인쇄, 전체 AI 채보, **다운로드(Guitar Pro, MIDI, MP3, WAV)**, 솔로·뮤트, 구간 반복, 피치 시프트, 음성 제어, 광고 제거 |

**우리에게 미치는 영향**
- 반복·감속·솔로/뮤트·피치 시프트를 **우리 앱에서 우리 코드로** 만드는 것은 "독립적인 도구"에 해당해 문제가 없습니다.
- Songsterr 탭으로 우리 채보 엔진을 평가하거나 학습시키면 안 됩니다. 개인용이라도 약관 문제입니다(저작권과는 별개).

## 1. Songsterr의 파이프라인

```
① 탭 만들기
   사용자 업로드·편집기 ───────┐
   AI 채보 (서버, 5–15분) ─────┼─→ 리비전(버전) 저장 ─→ 트랙별 JSON (CDN, 미러 3곳)
     입력: 유튜브 링크 / 음원 파일 │                          │
     힌트: 첫 마디 박자표·못갖춘마디·│                          ├─→ 서버 렌더 트랙별 음원 (Opus) + MIDI
           첫 템포·셋잇단 느낌·    │                          │     = "Songsterr Engine" 소리
           악기·튜닝·카포          │
     출력: 악기별 트랙 + 주법      │
           (벤딩·비브라토·슬라이드·팜뮤트)
     결과 탭은 입력한 녹음에 싱크된 상태로 나옴

② 원곡 연결 (서버 자동)
   누구나 유튜브 링크 제안 ─→ 서버 자동 싱크 ─→ video points (마디별 시간)
   알림: "싱크를 시작했어요, 끝나면 알려 드릴게요"
   실패 조건: 너무 긴 영상, 라이브 방송 영상
   결과는 "수정(edit)"으로 적용되고, 편집기에서 손으로 고칠 수 있음

③ 사용자 음원
   원곡이나 커버 녹음 업로드 ─→ 서버에서 반주 트랙 / 솔로 트랙 생성 (크레딧)
   유튜브에서 반주·솔로 트랙 요청 (하루 할당량)

④ 재생 (브라우저)
   소리 고르기: FluidSynth(WASM, MIDI 실시간) │ 서버 렌더 Opus │ 유튜브 │ 업로드 음원 │ 분리 음원
        └─→ 오디오 워커: signalsmith-stretch / SoundTouch (속도·피치)
        └─→ 메트로놈: 클릭 + 음성 카운트 1~8 (업로드·분리 음원과는 같이 못 씀)
   화면: 탭 한 줄 = SVG 하나
```

## 2. 기술 스택

| 층 | Songsterr가 쓰는 것 | 근거 |
|---|---|---|
| 화면 | **Preact**, CSS 모듈(해시 클래스 이름) | 확인 — 번들 이름, DOM |
| 탭 그리기 | **탭 한 줄마다 SVG 하나**. 숫자는 `<text>`, 줄·기둥은 `<path>`·`<line>`, 기호는 자체 웹폰트 `songsterr`. 캔버스는 안 씀 | 확인 — 렌더된 탭 페이지 |
| 상태 관리 | Redux 형태의 단일 저장소(슬라이스·thunk)를 **웹 워커 안에서** 돌림 | 확인 — `StoreWorker-*.js`, 상태 JSON의 `runningThunks` |
| 번들러 | **Rolldown** (Vite 계열, 우리와 같음) | 확인 — `rolldown-runtime-*.js` |
| 서버 렌더 | 페이지마다 `<script id="state">`에 초기 상태를 JSON으로 넣음 | 확인 — 페이지 HTML |
| 운영 | nginx, Sentry(오류 수집), Stripe(결제), Google Tag Manager, 쿠키 기반 A/B 실험 | 확인 — 응답 헤더, 스크립트, `experiments` 상태 |
| 탭 데이터 | 리비전마다, 트랙마다 JSON 파일 하나. CloudFront 3곳에서 서로 대체됨 | 확인 — 요청 형태 |
| 메타 정보 | 트랙 목록, 악기, **튜닝을 MIDI 번호로** (예: 베이스 `[41,36,31,26]`), 난이도, `aiGenerated` 플래그, 연결된 유튜브 영상 목록 | 확인 — 상태 JSON |
| 재생 ① | **FluidSynth 2.6.1 (WASM)** + SF3 사운드폰트, 전용 워커에서 실시간 합성 | 확인 — `libfluidsynth-2.6.1-sf3-*.wasm` |
| 재생 ② | 서버가 미리 렌더한 트랙별 **Opus** + 탐색용 인덱스 파일, 미러 3곳, HTTP Range 요청. 속도·솔로/뮤트·악기 조합마다 따로 캐시 | 확인 — 요청 형태, "Songsterr Engine 소리로 전환 (V)" 버튼, 도움말 |
| 속도·피치 | **signalsmith-stretch** (WASM, 고음질) + **SoundTouch** (가벼운 대안), AudioWorklet | 확인 — 오디오 워커 코드 |
| 메트로놈 | 클릭·강박 클릭 + **음성 카운트 1~8**. 업로드 음원·분리 음원과는 같이 못 씀 | 확인 — 파일 이름, 안내 문구 |
| 원곡 싱크 | 유튜브 IFrame 플레이어(`YT.Player`, `setPlaybackRate`) + **video points (마디별 시간)** | 확인 — 번들, 상태 JSON |
| 싱크 만들기 | **서버 자동 싱크.** 누구나 유튜브 링크를 제안하면 서버가 싱크하고 끝나면 알림. 너무 긴 영상·라이브 영상은 실패. 결과는 편집으로 적용되고 손으로 고칠 수 있음. 탭 구조를 바꾸면 자동 싱크를 다시 돌리는 기능도 있음 | 확인(문구) — "Autosynchronization started. We'll notify you when it is ready", "This video is too long to sync", "Autosynchronization is applied as edits", "Autosync After Structure Edit" |
| 싱크 알고리즘 | 서버 쪽이라 알 수 없음. API 이름에 자동·제안·수동·검증 단계가 있음 | 추정 |
| 싱크 규모 | 곡 하나(Come As You Are)에 유튜브 영상 **70개**가 각각 싱크됨: 다른 버전·커버 60, 반주 6, 솔로 2, 플레이스루 1, 기본(원곡) 1 | 확인 — 상태 JSON. "기본"이라는 이름은 문구 "Switch to the main video…"로 확인 |
| 사용자 음원 | 원곡이나 커버 녹음을 올리면 **서버가 반주 트랙·솔로 트랙을 만듦** (크레딧, 실패하면 반환) | 확인(문구) — "Backing track is still being created for your audio...", "Upload original recording or cover" |
| 유튜브 분리 요청 | 반주 / 솔로 트랙 요청, 24시간 단위로 회복되는 할당량 | 확인(문구) |
| AI 채보 | 입력: 유튜브 링크 또는 음원 파일. 힌트: 첫 마디 박자표, 못갖춘마디 길이, 첫 템포, 셋잇단 느낌, 악기, 튜닝(기타 6–8현, 베이스 4–6현), 카포. 출력: 리듬·리드 기타, 베이스, 드럼, 보컬, 피아노 등 트랙별, **주법 포함**(벤딩, 비브라토, 슬라이드, 팜뮤트). 결과는 입력 녹음에 싱크됨. 5–15분, 끝나면 이메일. 무료는 20초 미리보기 | 확인 — 도움말, AI 채보 페이지 |
| AI 모델 | 서버 쪽이라 알 수 없음 | — |
| AI 보조 | 편집기의 **마디 자동완성**(한도 있음), 화성으로 코드 자동 배치, 트랙 자동 전환(같은 파트가 여러 트랙에 나뉜 경우), 챗봇 | 확인 — 도움말, API 이름, 버튼 |
| 연주 따라가기 | **Live Scroll**: 마이크로 연주를 듣고 화면이 따라옴 (신뢰도, 입력 레벨, 튜닝 힌트) | 확인 — `getUserMedia`, `liveScroll` 상태 |
| 편집기 | 운지 규칙 엔진, 리비전 비교(diff), 개인 초안 자동 저장, MusicXML, 조옮김, 오디오 지연 보정 | 확인 — 도움말, 상태 JSON, 번들 |

## 3. 우리 앱과 비교

| 영역 | Songsterr | bass_tab_maker | 차이 |
|---|---|---|---|
| 탭 출처 | 사용자 기여 라이브러리 + AI 채보 | 사용자의 .gp + 자동 채보(초안) | 라이브러리는 우리가 가질 수 없음 |
| 탭 표시 | 줄마다 SVG (자체 렌더러) | alphaTab (역시 SVG) | 같은 방식 |
| 신디 재생 | FluidSynth WASM + 사운드폰트 | alphaTab 신디 + sonivox 사운드폰트 | 같은 방식 |
| 서버 렌더 음원 | 있음 | 없음 | 필요 없음 (서버가 없는 구조) |
| 원곡 싱크 데이터 | 마디별 시간 (video points) | 마디별 앵커 (`synthTick → audioMs`) | **같은 구조** |
| 싱크 만들기 | 서버 자동 싱크 + 손 수정 | 브라우저 자동 싱크 (DTW 정렬, `align.ts`) + 앵커 모드로 손 수정 | 우리는 서버 없이 몇 초 |
| 곡당 녹음 | 여러 개 (다른 버전·반주·솔로) | 한 개 | **추가 후보** |
| 음원 분리 | 서버 | 브라우저 (Demucs) 또는 로컬 도우미 | 비슷 |
| 채보 | 서버 AI, 악기 전부, 주법 포함, 녹음에 싱크된 결과 | 브라우저 신호처리 엔진, 베이스만, 주법 없음, 녹음에 싱크된 결과 | **정확도는 실제 녹음으로 재야 함** |
| 채보 힌트 | 박자표·못갖춘마디·템포·셋잇단·튜닝·카포를 미리 입력 | 템포(BPM) 입력, 결과에서 마디 시작·박자·템포 단계 고치기 | 못갖춘마디·셋잇단·5/6현 후보 |
| 속도 | 감속 (Plus), signalsmith-stretch | 25–125%, 브라우저 기본 재생 속도 | 음질 개선 여지 |
| 피치 시프트 | 있음 (Plus) | 없음 | **추가 후보** |
| 구간 반복·카운트인·메트로놈 | 있음 | 있음 | — |
| 음성 카운트 | 있음 | 없음 | 작은 후보 |
| 솔로·뮤트 | 있음 | 원본 / 베이스만 / 반주만 전환 | 악보 트랙별 뮤트는 없음 |
| 연주 따라가기 (마이크) | Live Scroll | 없음 | 장기 후보 |

## 4. 가져올 만한 것 (우리 코드로 직접 구현)

| 순위 | 후보 | 효과 | 작업량 | 메모 |
|---|---|---|---|---|
| 1 | **signalsmith-stretch로 피치 시프트 + 고음질 감속** | 반음 내린 튜닝 곡 연습, 느린 재생 음질 | 중 | README "왜 이렇게 짰는지 4번"의 교체 지점(`originalTrack.ts`). 라이선스 확인 필요 (MIT로 알고 있음) |
| 2 | **곡 하나에 녹음 여러 개** (라이브, 커버, 반주 트랙) 각각 자동 싱크 | 같은 탭으로 여러 버전 연습 | 중 | `align.ts`는 그대로 쓰고, 문서 모델과 UI만 바꾸면 됨 |
| 3 | 채보 전 힌트: 못갖춘마디, 셋잇단 느낌, 5·6현 베이스 | 채보 정확도 (첫 마디·리듬·운지) | 중 | 지금은 BPM만 받음 |
| 4 | 싱크 검토 흐름: 일치도 낮은 마디를 보여 주고 그 자리에서 고치기 | 자동 싱크가 틀린 곳을 빠르게 수정 | 소~중 | 이미 마디별 일치도(`weakBars`)가 있음 |
| 5 | 음성 카운트인 | 연습 편의 | 소 | 녹음 샘플이나 음성 합성 필요 |
| 6 | 악보 트랙별 솔로·뮤트 | GP 파일의 기타·드럼과 같이 연습 | 소 | alphaTab에 기능 있음 |
| 7 | 주법 (슬라이드, 해머온, 고스트노트) 채보 | 탭의 완성도 | 대 | 정확도 측정 체계가 먼저 |
| 8 | 마이크 연주 따라가기 | 손 대신 연주로 스크롤 | 대 | 나중에 |

필요 없다고 보는 것: 서버 렌더 음원(alphaTab 신디로 충분), AI 마디 자동완성, 챗봇.

## 5. 하지 않을 것

- Songsterr의 탭 JSON, 오디오, `/api/`를 우리 앱이나 스크립트에서 직접 쓰기
- Plus 기능 우회
- Songsterr 탭이나 AI 결과로 우리 채보 엔진을 학습·평가하기 (ai.txt가 금지)
- Songsterr의 코드, 소리, 디자인 에셋 복사

**합법적으로 이어지는 길**
- Plus 사용자가 공식 다운로드로 받은 Guitar Pro 파일을, 우리 앱의 **"이 곡에 기존 악보 넣기"**로 넣으면 자기 음원에 자동 싱크됩니다. 개인 연습 용도입니다.

## 6. 결정된 것과 다음 단계

- 앱은 **개인용**으로 갑니다.
- 목표는 **원본 악보가 없어도 정확한 채보**입니다. 그래서 다음 작업은 채보 정확도를 실제에 가까운 음원으로 재는 체계입니다.
  - 1순위: **공개 데이터셋으로 자동 채점** — Slakh2100 일부 (실제 곡 형태의 믹스 + 베이스 MIDI 정답)
  - 그다음: 실제 원곡 + 정식 악보(Songsterr 제외)를 자동 싱크로 맞춰 정답으로 쓰기
  - 여유가 있을 때: 직접 녹음한 DI 베이스 + 실제 반주
- 4장의 기능 후보는 정확도 체계가 선 뒤에 다시 고릅니다.
