# Songsterr 기술 분석 — 우리 앱에 참고할 것

조사일: 2026-11-09. 대상: <https://www.songsterr.com>

목적은 bass_tab_maker 설계에 참고하는 것입니다. Songsterr의 콘텐츠를 가져다 쓰려는 것이 아닙니다. 아래 내용은 모두 공개 페이지를 관찰해서 얻었고, 서버 쪽 동작은 API 이름에서 추정한 것입니다. 추정은 따로 표시했습니다.

---

## 0. 조사 방법과 지킨 규칙

**본 것**
- `robots.txt`, `ai.txt`
- 홈페이지 1개, 탭 페이지 1개 (Nirvana – Come As You Are)
- 페이지에 들어 있는 서버 렌더 상태(JSON)의 **구조** — 키 이름과 메타 정보만
- 헤드리스 Chromium으로 페이지를 열었을 때 나간 요청의 종류와 주소 형태 (응답 내용은 저장하지 않음)
- 공개 스크립트 번들에서 쓰는 라이브러리 이름 확인 (키워드 검색 후 파일 삭제)

**보지 않은 것**
- 탭 내용(음표) JSON, 오디오 파일, `/api/` 직접 호출
- 로그인, Plus 기능

**접근 방식**
- curl로는 탭 페이지가 403으로 막혔습니다. 브라우저인 척 위장하지 않았습니다.
- 헤드리스 Chromium은 기본 user agent 그대로 썼습니다.

### Songsterr의 정책 (robots.txt, ai.txt 요약)

| 구분 | 내용 |
|---|---|
| 허용 | 사용자 대신 탭 열기·보기, 재생·정지·위치 이동, 연주법 설명, **사이트를 건드리지 않는 독립적인 도구 만들기** |
| 금지 | Songsterr 콘텐츠(탭, 메타데이터, 오디오, API 응답)로 AI 모델을 **학습·미세조정·평가**하는 것, 그런 데이터셋을 만드는 것 (서면 허가 없이) |
| 금지 | Plus 기능을 스크립트, 플레이어 조작, 응답 변조 등으로 우회하는 것 |
| 크롤러 | `/api/`, 오디오 CDN 경로 등은 크롤링 금지. AI 학습용 크롤러(GPTBot, ClaudeBot 등)는 전체 금지 |
| Plus 기능 | 원곡 오디오와 끊김 없는 싱크, 감속, 인쇄, 전체 AI 채보, **다운로드(Guitar Pro, MIDI, MP3, WAV)**, 솔로·뮤트, 구간 반복, 피치 시프트, 음성 제어, 광고 제거 |

**우리에게 미치는 영향**
- 반복·감속·솔로/뮤트·피치 시프트를 **우리 앱에서 우리 코드로** 만드는 것은 "독립적인 도구"에 해당해 문제가 없습니다.
- Songsterr 탭으로 우리 채보 엔진을 평가하거나 학습시키면 안 됩니다.

## 1. Songsterr의 파이프라인

```
① 탭 만들기
   사용자 업로드·편집기 ──┐
   AI 채보 (서버) ─────────┼─→ 리비전(버전) 저장 ─→ 트랙별 JSON (CDN, 미러 3곳)
                           │                          │
                           │                          ├─→ 서버가 미리 렌더한 트랙별 음원 (Opus) + MIDI
                           │                          │     = "Songsterr Engine" 소리
② 원곡 연결
   유튜브 영상 여러 개 ─→ video points (마디별 시간)
                          자동 생성 → 제안 → 수동 수정 → 검증          (서버, 추정)

③ 사용자 음원
   업로드 ─→ 서버에서 분리 (솔로 / 반주) ─→ 싱크 포인트                 (서버, 추정)

④ 재생 (브라우저)
   음원 고르기: FluidSynth(WASM, MIDI 실시간) │ 서버 렌더 Opus │ 유튜브 │ 사용자 음원
        └─→ 오디오 워커: signalsmith-stretch / SoundTouch (속도·피치)
        └─→ 메트로놈: 클릭 + 음성 카운트 1~8
```

## 2. 기술 스택

| 층 | Songsterr가 쓰는 것 | 근거 |
|---|---|---|
| 화면 | **Preact** | 번들 이름 `preact-*.js` |
| 상태 관리 | Redux 형태의 단일 저장소(슬라이스·thunk)를 **웹 워커 안에서** 돌림 | `StoreWorker-*.js`, 상태 JSON의 `runningThunks` |
| 번들러 | **Rolldown** (Vite 계열, 우리와 같음) | `rolldown-runtime-*.js` |
| 서버 렌더 | 페이지마다 `<script id="state">`에 초기 상태를 JSON으로 넣음 | 페이지 HTML |
| 운영 | nginx, Sentry(오류 수집), Stripe(결제), Google Tag Manager, 쿠키 기반 A/B 실험 | 응답 헤더, 스크립트, `experiments` 상태 |
| 탭 데이터 | 리비전마다, 트랙마다 JSON 파일 하나. CloudFront 3곳에서 서로 대체됨 | 요청 형태 |
| 메타 정보 | 트랙 목록, 악기, **튜닝을 MIDI 번호로** (예: 베이스 `[41,36,31,26]`), 난이도, `aiGenerated` 플래그, 연결된 유튜브 영상 목록 | 상태 JSON |
| 재생 ① | **FluidSynth 2.6.1 (WASM)** + SF3 사운드폰트, 전용 워커에서 실시간 합성 | `libfluidsynth-2.6.1-sf3-*.wasm`, `FluidsynthAudioPlayerWorkerEntry` |
| 재생 ② | 서버가 미리 렌더한 트랙별 **Opus** + 탐색용 인덱스 파일, 미러 3곳, HTTP Range 요청 | 요청 형태, "Songsterr Engine 소리로 전환 (V)" 버튼 |
| 속도·피치 | **signalsmith-stretch** (WASM, 고음질) + **SoundTouch** (가벼운 대안), AudioWorklet | 오디오 워커 코드 |
| 메트로놈 | 클릭·강박 클릭 + **음성 카운트 1~8** 샘플 | Opus 파일 이름 |
| 원곡 싱크 | 유튜브 IFrame 플레이어(`YT.Player`, `setPlaybackRate`) + **video points (마디별 시간)** | 번들, 상태 JSON |
| 싱크 생성 | 서버 API: 자동(`auto`) · 제안(`suggest`) · 수동(`manual`) · 처리(`process`) · 검증(`verify`) · 수정본(`edited`) · 다른 영상(`alt-video`) | 번들의 API 경로 이름 (추정) |
| 싱크 규모 | 곡 하나(Come As You Are)에 유튜브 영상 **70개**가 각각 싱크됨: 다른 버전 60, 반주 6, 솔로 2, 플레이스루 1, 기본 1 | 상태 JSON |
| 사용자 음원 | 업로드 → 서버 분리(솔로·반주) → 싱크 포인트 | `userAudio` 상태, API 이름 (추정) |
| 유튜브 분리 요청 | 반주 / 솔로 트랙을 요청 (할당량 있음) | `bt-request` API |
| AI 채보 | 곡·트랙·사용자 파일 채보, 다시 생성 — 서버, 크레딧제. 생성되는 마디를 실시간으로 보여 주는 화면 | API 이름, `aiTabOverlay` 상태 |
| AI 보조 | 편집기의 **마디 자동완성**(한도 있음), 화성으로 코드 자동 배치, 챗봇 | API 이름, 버튼 |
| 연주 따라가기 | **Live Scroll**: 마이크로 연주를 듣고 화면이 따라옴 (신뢰도, 입력 레벨, 튜닝 힌트) | `getUserMedia`, `liveScroll` 상태 |
| 편집기 | 운지 규칙 엔진, 리비전 비교(diff), MusicXML, 조옮김, 오디오 지연 보정 | 상태 JSON, 번들 |
| 확인 못 함 | 탭을 SVG로 그리는지 캔버스로 그리는지 (탭 데이터를 받지 않아 화면에 안 그려짐), AI 모델의 종류 | — |

## 3. 우리 앱과 비교

| 영역 | Songsterr | bass_tab_maker | 차이 |
|---|---|---|---|
| 탭 출처 | 자체 라이브러리 + AI 채보 | 사용자의 .gp + 자동 채보(초안) | 라이브러리는 우리가 가질 수 없음 |
| 탭 표시·재생 | 자체 렌더러 + FluidSynth WASM | alphaTab (렌더 + sonivox 사운드폰트 신디) | 비슷한 방식 |
| 서버 렌더 음원 | 있음 | 없음 | 필요 없음 (서버가 없는 구조) |
| 원곡 싱크 데이터 | 마디별 시간 (video points) | 마디별 앵커 (`synthTick → audioMs`) | **같은 구조** |
| 싱크 만들기 | 서버 자동 + 제안/검증 | 브라우저에서 자동 (DTW 정렬, `align.ts`) + 앵커 모드로 수동 수정 | 우리는 서버 없이 자동 |
| 곡당 녹음 | 여러 개 (다른 버전·반주·솔로) | 한 개 | **추가 후보** |
| 음원 분리 | 서버 | 브라우저 (Demucs) 또는 로컬 도우미 | 비슷 |
| 채보 | 서버 AI (모델 비공개) | 브라우저 신호처리 엔진 (`src/lib/tab`) | 실제 녹음 검증은 아직 |
| 속도 | 감속 (Plus) | 25–125%, 브라우저 기본 재생 속도 | 음질 개선 여지 |
| 피치 시프트 | 있음 (Plus) | 없음 | **추가 후보** |
| 구간 반복·카운트인·메트로놈 | 있음 | 있음 | — |
| 음성 카운트 | 있음 | 없음 | 작은 후보 |
| 솔로·뮤트 | 있음 | 원본 / 베이스만 / 반주만 전환 | 악보 트랙별 뮤트는 없음 |
| 연주 따라가기 (마이크) | Live Scroll | 없음 | 장기 후보 |

## 4. 가져올 만한 것 (우리 코드로 직접 구현)

| 순위 | 후보 | 효과 | 작업량 | 메모 |
|---|---|---|---|---|
| 1 | **signalsmith-stretch로 피치 시프트 + 고음질 감속** | 반음 내린 튜닝 곡 연습, 느린 재생 음질 | 중 | README "왜 이렇게 짰는지 4번"의 교체 지점(`originalTrack.ts`). 라이선스 확인 필요 (MIT로 알고 있음) |
| 2 | **곡 하나에 녹음 여러 개** (라이브, 커버, 반주 트랙) 각각 자동 싱크 | 같은 탭으로 여러 버전 연습 | 중 | `align.ts`는 그대로 쓰고, 문서 모델과 UI만 바꾸면 됨 |
| 3 | 싱크 검토 흐름: 일치도 낮은 마디를 보여 주고 그 자리에서 고치기 | 자동 싱크가 틀린 곳을 빠르게 수정 | 소~중 | 이미 마디별 일치도(`weakBars`)가 있음 |
| 4 | 음성 카운트인 | 연습 편의 | 소 | 녹음 샘플이나 음성 합성 필요 |
| 5 | 악보 트랙별 솔로·뮤트 | GP 파일의 기타·드럼과 같이 연습 | 소 | alphaTab에 기능 있음 |
| 6 | 마이크 연주 따라가기 | 손 대신 연주로 스크롤 | 대 | 나중에 |

필요 없다고 보는 것: 서버 렌더 음원(alphaTab 신디로 충분), AI 마디 자동완성, 챗봇.

## 5. 하지 않을 것

- Songsterr의 탭 JSON, 오디오, `/api/`를 우리 앱이나 스크립트에서 직접 쓰기
- Plus 기능 우회
- Songsterr 탭이나 AI 결과로 우리 채보 엔진을 학습·평가하기 (ai.txt가 금지)
- Songsterr의 코드, 소리, 디자인 에셋 복사

**합법적으로 이어지는 길**
- Plus 사용자가 공식 다운로드로 받은 Guitar Pro 파일을, 우리 앱의 **"이 곡에 기존 악보 넣기"**로 넣으면 자기 음원에 자동 싱크됩니다. 개인 연습 용도입니다.

## 6. 상의할 것

1. 4장 후보의 순서: 1번(피치 시프트·고음질 감속)부터 갈지, 2번(녹음 여러 개)부터 갈지
2. 채보 엔진의 정확도는 Songsterr 대신 무엇으로 잴지 — 실제 녹음과 그 곡의 정식 악보(.gp)를 사용자가 직접 준비한 경우에 한해
3. 배포 계획: 지금처럼 개인 로컬 앱인지, 공개 배포인지 — 배포하면 저작권 안내 문구가 필요
